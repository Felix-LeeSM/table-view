# ci-uncalled-tests.txt — CI 가 안 부르는 src-tauri 통합 테스트 binary 의 allowlist (issue #2113).
#
# `scripts/check-ci-test-calls.sh` 가 읽는다. 그 스크립트가 미호출로 판정한 통합
# 테스트 target 은 전부 여기 사유와 함께 있어야 하고, 없으면 CI 의
# `PR Body Contract` 가 red 다. 무엇을 target 으로 치고 무엇을 호출로 치는지는 그
# 스크립트 헤더가 SOT 다 — 같은 규칙을 여기 다시 적으면 게이트가 바뀌는 날 이
# 사본만 낡는다.
#
# 형식: 한 줄에 `<테스트 이름><공백><사유>`. `#` 로 시작하는 줄과 빈 줄은 무시하고,
# 사유가 비면 위반이다. 정렬은 관례일 뿐 가드는 순서를 안 본다.
#
# ## 줄을 지워야 하는 때
#
# 이 파일은 줄어들기만 한다. 테스트를 workflow 의 `--test` 로 부르기 시작했거나
# 파일을 지웠으면 여기 줄도 같은 PR 에서 지운다 — 둘 다 가드가 위반으로 잡는다.
#
# ## 사유 `measured-2559` 는 시딩분을 실행해서 얻은 판정이다
#
# 이 사유가 붙은 줄은 이 게이트가 생기기 전부터 미호출이던 시딩분이고, 처음 사유는
# `seed-2113` 이었다. #2559 가 `fd557c1104e6` 트리에서 줄마다 아래 명령을 로컬
# (macOS aarch64, Docker 기동)로 돌렸고, 첫 실행의 결과를 판정으로 삼아 사유를
# `measured-2559 <판정> <근거 요약>` 으로 바꿨다.
#
#   cargo test --manifest-path src-tauri/Cargo.toml --test <이름> -- --nocapture
#
#   fail = rc 가 0 이 아니다
#   skip = rc 는 0 이지만 통과한 테스트가 0 개이거나 출력에 `SKIP:` 줄이 있다
#   pass = rc 가 0 이고 통과한 테스트가 1 개 이상이며 `SKIP:` 줄이 없다
#
# `*_HOST` 환경 변수 없이 돌렸으므로, 서버 DB 에 붙는 target 은 테스트 helper 가 직접
# 띄운 testcontainers 컨테이너를 썼다 (근거 요약 끝 괄호의 이미지). 판정은 그 트리에서
# 잰 값이지 CI 결과가 아니다.
# pass · skip 을 CI 에 붙이는 일은 #2705 가 맡고, fail 을 고치는 일은 target 마다
# 따로 여는 이슈가 맡는다. 판정별 이름은 아래 명령으로 뽑는다 (`pass` 자리를 바꿔
# 쓴다):
#
#   awk '$1 !~ /^#/ && $2 == "measured-2559" && $3 == "pass" {print $1}' ci-uncalled-tests.txt
#
# 새로 추가하는 줄은 측정분이 아니므로 진짜 사유를 적어라.
#
# 이 파일의 이름 집합은 게이트가 세는 미호출 집합과 정확히 같아야 한다. 지금 값은
