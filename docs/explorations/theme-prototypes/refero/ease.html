-- 최근 30일 고객별 매출
SELECT c.id, c.name, SUM(o.total_amount) AS revenue
FROM orders o
JOIN customers c ON c.id = o.customer_id
WHERE o.created_at >= NOW() - INTERVAL '30 days'
AND o.status <> 'cancelled'
GROUP BY c.id, c.name
HAVING SUM(o.total_amount) > 1000
ORDER BY revenue DESC
LIMIT 50;

디자인 노트

  • 표면 겹침. 그림자 없이 틴트 5겹만으로 깊이를 만들었다 — Cream(배경·그리드·에디터) → Keylime(카드·사이드바) → Mint(선택·강조) → Sage(툴바·상태바) → Slate(팝오버·인스펙터). 페이지 전체에 box-shadow 는 하나도 없다.
  • 카드 패딩 vs 그리드 밀도. "카드 패딩 21px 이상" 규칙은 카드/패널의 바깥 프레임에만 적용했다 — 그리드를 감싸는 패널은 28px, SQL 에디터 패널은 21px. 그 안쪽은 도구 밀도를 우선해 그리드 셀 11px/7px, 사이드바 트리 행 11px/7px 로 조밀하게 갔다. 매트에 끼운 인화지처럼, 여백은 프레임이 갖고 데이터 자체는 촘촘하다.
  • dark 모드. 반전이 아니라 "온실을 밤으로 옮긴 판본"이다. 바닥을 Forest Shadow로 낮추고 같은 다섯 겹 순서를 이번엔 밝아지는 방향으로 다시 쌓았다(카드→액센트→세컨더리→팝오버 순으로 점점 밝고 차가워진다). 그림자 없음과 radius 는 그대로 두고, primary 만 Forest Ink 대신 밝은 스프링그린으로 뒤집어 어두운 배경 위에서 읽히게 했다.
  • 구문 강조. Forest Ink·Olive·Teal·Plum 네 계열을 12개 역할에 나눠 썼고, sage/keylime 같은 밝은 표면색은 금지 규칙대로 텍스트에 한 번도 쓰지 않았다 — 전부 배경 대비 4.5:1 이상 확인 후 확정했다(라이트 5.05~12.10:1, 다크 4.44~9.58:1).
  • 고정 시맨틱 색. destructive/success/warning/highlight 는 SPEC 이 고정한 값이라 손대지 않았다. 대신 옅은 배경 위 텍스트로는 한 번도 쓰지 않고 항상 배지·버튼의 배경으로 채운 뒤 라이트는 Charcoal, 다크는 Forest Shadow 로 텍스트를 앵커링했다 — destructive 라이트 버튼만 4.23:1 로 4.5 에 살짝 못 미치는데, SPEC 이 고정한 레드 자체의 한계다.
