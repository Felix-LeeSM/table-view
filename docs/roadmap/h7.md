# H7 진행 기준

H7 운영/보안/신뢰성은 **자동 gate 와 support claim 을 실제 설정에 맞추는 정합성
gate**다. H7 closure 는 a11y/perf/link-check/platform smoke 가 routine blocking
gate 로 새로 승격되었다는 뜻이 아니다. 새 gate 는 active feature lane 을 실제로
막고, owner 와 runtime cost 가 분명하며, failure triage 경로가 갖추어졌을 때에만
승격한다.

| Gate | Current owner | H7 boundary |
|---|---|---|
| PR/main CI gates | `.github/workflows/ci.yml`, `.github/workflows/e2e-smoke.yml` | The merge-blocking set is listed once, in `memory/runbook/pr-merge-gates/memory.md`; this row keeps no copy of it. Every required context can fail: the last name-only pair went on 2026-07-31, when `Detect Change Scope` was dropped from both the ruleset and `ci.yml` and `PR Body Contract` became a real check. Full a11y, perf, link-check, and cross-platform runtime smoke are not routine blocking gates. |
| Local hook gates | `memory/workflow/git-policy/memory.md` | There are none. No git hook runs locally, so bypass flags, unsigned commits, pull/reset recovery hazards, and force-push are forbidden by policy alone, with nothing enforcing it. |
| Fixture/test topology | `memory/engineering/conventions/testing-scenarios/fixtures/memory.md`, `docs/contributor-guide/fixture-test-topology-inventory.md`, `docs/contributor-guide/testing-and-quality.md` | Refactor 04 fixture/test topology closes only when DBMS-first fixture roots, test placement, support-claim boundaries, and smoke-routing tiers stay aligned. Fixture existence is contract evidence only until a consuming test plus product-doc review plus smoke-routing decision promotes it. Live GitHub audit on 2026-06-12 shows parent #575 and milestone #40 closed after #755 and the remaining Refactor 04 children landed. |
| Runtime E2E smoke | `wdio.smoke.conf.ts`, `e2e/smoke/**`, `e2e/scope-map.mjs` | `Runtime Happy Path` runs the specs a change's paths select, and every spec on push to `main` / nightly schedule / `workflow_dispatch` (#2038). A support claim citing remote smoke now cites a run, and must name which one: a PR run covers only its selected subset. Cross-platform (macOS/Windows) runtime smoke is still hand-run evidence only (README 「E2E Smoke」). |
| Security/destructive policy | `docs/product/query-language-support.md`, `docs/product/known-limitations.md` | Current destructive protections are source-specific preview/confirm/Safe Mode/typed confirmation paths. There is no universal admin/security dashboard, role/user/permission UI, credential rotation UI, or global audit-log claim. Security-impacting decisions follow a threat-model review before option selection. |
| Credential/privacy boundary | `memory/engineering/architecture/state-management/memory.md`, `docs/product/README.md`, `docs/product/known-limitations.md` | Table View remains local-first. Connection export omits passwords, imported connections require password re-entry, and local file analytics public payloads redact absolute paths. 2026-07-25 오너 grill 에서 실측한 결과는 다음과 같다. export 산출물에 비밀번호가 없다는 것과 import 시 비밀번호를 다시 입력하도록 강제한다는 것은 `src-tauri/src/commands/connection/io.rs` 의 단위 테스트가 덮고, 로컬 파일의 절대경로를 redaction 하는 것은 `src-tauri/table-view-core/src/db/duckdb/file_analytics.rs` 와 `e2e/smoke/duckdb-file-analytics.spec.ts` 가 덮는다. 실제 Rust backend 를 관통하는 export 에서 import 로 이어지는 왕복은 `e2e/smoke/connection-export-import.spec.ts` 가 덮는다 (#1815). 앱에는 파일 기반 평문 export UI 가 없다. `ImportExportDialog` 는 textarea 와 클립보드만 쓰고, `ExportPanel` 의 export 호출은 `exportConnectionsEncrypted` 하나뿐이다 (그 자리는 `git grep -n 'exportConnectionsEncrypted(' -- src/features/connection/components/ImportExportDialog.tsx` 가 낸다. 줄 번호를 여기에 적어 두면 그 파일을 다음에 편집할 때 이 줄이 거짓이 된다). 그 불변식을 잠그는 것은 ADR 이 아니라 AC-149-4/-5 다 (`src/features/connection/components/ImportExportDialog.ac149.test.tsx:185`·`:221`). 그 spec 은 「파일로 내보낸다」가 아니라 아래의 속성으로 판정한다: export 산출물에 비밀번호가 없고, import 본은 비밀번호를 다시 입력해야 하며, 표시된 mnemonic 은 성공하고 틀린 mnemonic 은 거부된다. Path C 디스크 fallback 을 거친 file-key 는 keyring 이 돌아온 부팅에서 자동으로 폐기된다 (#1814): 새 키 생성 → keyring 덮어쓰기 → `connections.json` 재암호화(임시 파일 + atomic rename) → 디스크 `.key` secure delete 순서이고, 디스크 `.key` 가 복구 앵커이므로 어느 단계에서 중단되어도 다음 부팅이 이어받는다. 수행 여부는 `KeyOutcome::rekeyed_after_disk_exposure` 가 보고한다. 구현은 `src-tauri/table-view-core/src/storage/key_migration.rs` 이고, 중단 지점 3곳에서 다음 부팅이 복구하는 것은 `src-tauri/tests/keyring_migration.rs` 가 덮으며, 재암호화가 실패해도 원본 `connections.json` 이 손상되지 않는 것은 같은 구현 파일의 인라인 테스트가 덮는다. 그 `keyring_*` 통합 binary 는 2026-08-02 까지 어떤 workflow 도 호출하지 않아 gate 가 아니었다 (`cargo test --test` 는 allowlist 다). `.github/workflows/ci.yml` 의 `Rust Unit And Storage Tests` job 이 `Run cargo tests` step 의 `--test` 목록으로 그 셋을 부른다. 같은 날 Path B 의 잔여 공백 셋도 `src-tauri/tests/keyring_migration.rs` 의 「#1815」 절이 메웠다: ciphertext probe 가 실패해도 디스크 `.key` 를 지우지 않는 것, 실패한 부팅이 남긴 sentinel 을 성공한 재시도가 회수하는 것, secure delete 가 unlink 하기 전에 실제로 바이트를 0 으로 덮어쓰는 것을 단언한다 (살아남은 hard link 로 관측한다). 그중 probe 는 그때까지 `password` 필드만 읽어서 secret 이 `wallet_password` 뿐인 프로필을 잘못 통과시켰고, 그 프로필은 (d) secure delete 까지 진행되었다. probe 가 `SECRET_FIELDS` 전체를 읽도록 넓힌 것은 #2124 다 (회귀는 `key_migration.rs` 의 인라인 테스트가 잡으며 `cd src-tauri && cargo test -p table-view-core --lib key_migration` 으로 돌린다). 주기적인 키 회전과 confirm UI, DB 비밀번호 교체 안내는 여전히 범위 밖이다. 이 재키잉은 keyring 이 살아 있는 부팅에서만 일어난다. Path B (디스크 `.key` 는 있고 keyring 엔트리는 없는 첫 복귀 부팅) 는 AC-356-02 계약대로 같은 키를 그대로 이주시키므로, 그 경로의 노출을 회수하는 일은 아직 열린 공백으로 남아 있다. |
| A11y/perf/link-check/platform smoke | `docs/contributor-guide/testing-and-quality.md`, `.github/workflows/ci.yml` | Existing component/unit checks and advisory theme contrast do not equal routine screen-reader, FPS/latency, link-check, macOS runtime, or Windows runtime gates. Promote only when a lane needs a concrete owner and budget. |

H7 umbrella closure means ops/security/reliability documentation, smoke matrices,
and known limitations no longer overstate the current automated gate surface. It
does not mean all H7 implementation gaps have shipped.
